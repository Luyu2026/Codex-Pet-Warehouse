# Codex Pet 美术流程结论

这份记录沉淀本次制作柯基、哈士奇、金毛宠物后确认下来的流程判断，后续制作新宠物时优先遵守。

## 核心结论

最终宠物美术不再用程序绘制。程序脚本只负责打包、清理透明背景、切格校验、方向修复、坏格补帧等工程处理；最终角色形象应通过图片生成流程完成。

原因很直接：程序绘制容易出现硬边矢量、几何块状、像素/图标感，和当前两只猫咪宠物的细腻软萌插画风不统一。图片生成更容易做出细腻毛边、柔和阴影、半立体贴纸感和自然表情。

## 推荐流程

1. 先选一个已经满意的宠物 spritesheet 作为风格锚点。当前狗狗类优先参考 `cream-orange-cat-coder` 和 `tuxedo-cat-coder`。
2. 再选用户给的照片作为身份锚点。比如柯基照片负责大耳、短腿、棕白脸；哈士奇照片负责黑白面罩、尖耳、眼睛；金毛照片负责金色长毛、垂耳、温柔表情。
3. 用图片生成流程生成候选 spritesheet 或预览图，先让用户确认风格。
4. 用户确认后，再用 `skills/codex-pet-maker/scripts/pet_atlas.py package` 打包。
5. 必须打开 `spritesheet-grid-check.png` 人工看红线检查图，确认没有重影、串格、漏格、裁切。
6. 必须检查方向：当前 Codex renderer 中第 2 行面向右、第 3 行面向左，实际移动时才会左跑向左、右跑向右。方向不对时只按单格镜像对应行，不倒序整行。
7. 必须在深色背景上检查第一帧和脸部/嘴部区域。白底检查图会隐藏透明洞、破碎深色遮罩和过黑的生成阴影，Codex 深色界面会把这些问题显示成黑色裂痕。
8. 如果只有少数坏格，可以用相邻好帧补齐；如果整体风格不对，重新生成美术，不要用脚本硬画最终图。

## 狗狗类风格标准

- 使用猫咪 spritesheet 的可爱插画感作为风格锚点。
- 保留品种身份：柯基大耳短腿、哈士奇黑白面罩、金毛垂耳长毛。
- 使用细腻毛边、柔和阴影、大眼睛、圆润比例和半立体贴纸感。
- 禁止作为默认最终美术：程序矢量图、像素画、扁平 emoji、硬黑线轮廓、几何块身体。

## 白色/浅色主体问题沉淀

兔子、白猫、浅色狗这类主体，不要默认要求白底或棋盘格背景。白毛和背景颜色太接近时，清背景脚本容易把脸、身体、爪子、耳朵边缘一起擦掉，导致预览像“缺块”。

更稳的做法：

- 生成阶段优先要求透明背景。
- 如果透明背景不稳定，就要求纯色浅青/浅蓝背景，后处理时按背景色抠掉。
- 不要把白底图直接交给通用清背景逻辑。
- 抠完后必须同时看白底格线图和深色背景图；白底图能看串格，深色背景能看白毛边缘和透明洞。

## 工具边界

`pet_atlas.py` 适合做：

- `package`: 清理背景、生成 `pet.json`、输出检查图。
- `validate`: 校验尺寸、透明度和元数据。
- `flip-rows`: 修正左右移动方向。
- 少量补帧：处理个别漏格或残影。

`pet_atlas.py` 不应该做：

- 从零绘制最终角色。
- 把照片程序化描成扁平图标。
- 用几何形状代替图片生成美术。
- 倒序整行来修方向。

## 方向问题沉淀

这几次最容易反复出错的是左右移动方向。后续统一按这个判断：

- 第 2 行必须是右移动，角色朝右。
- 第 3 行必须是左移动，角色朝左。
- 只修朝向时使用 `flip-rows`，它会镜像每个单格但保留动画帧顺序。
- 如果 Codex 里显示仍旧反向，先确认本机 `~/.codex/pets/<pet-id>/spritesheet.png` 是否和仓库哈希一致，再重启 Codex 排除缓存。
- 涉及 Git 提交或推送前，必须完成本机安装、仓库和本机哈希比对、以及方向复核，避免把未同步的方向修复推上去。

## 本机安装问题沉淀

覆盖本机已有宠物时，不要运行 `cp -R pets/<pet-id> ~/.codex/pets/<pet-id>`。如果目标目录已经存在，这会生成 `~/.codex/pets/<pet-id>/<pet-id>`，Codex 仍然读取外层旧文件，看起来就像“没有更新”。

正确写法是复制目录内容：

```bash
mkdir -p ~/.codex/pets/<pet-id>
cp -R pets/<pet-id>/. ~/.codex/pets/<pet-id>/
```
